# 《宽带线索商机》更新上传操作指南（详细版）

> 适用对象：不使用 Git 命令行、用 GitHub 网页上传/更新的零基础用户。
> 核心要点一句话：**每个文件必须传到它在项目里的正确文件夹位置，放错文件夹 = 应用不生效（重点！）**

---

## 〇、先搞懂项目文件放哪里（最重要）

项目里文件是有「文件夹结构」的，**不能全部堆在仓库根目录**。必须按下面的对应关系放到 GitHub 的对应文件夹里：

| 你要上传的文件 | 在 GitHub 里要放进哪个文件夹 |
|---|---|
| `index.html` | 仓库**根目录**（最外层，不和任何文件夹混） |
| `sw.js`、`manifest.json` | 仓库**根目录** |
| `icon-192.png`、`icon-512.png` | `assets` 文件夹 |
| `diag.html` | 仓库**根目录** |
| `store.js`、`router.js`、`app.js` | `js` 文件夹 |
| `input.js`、`detail.js`、`home.js`、`stats.js`、`mine.js`、`share.js`、`guide.js` | `js` → `pages` 文件夹 |
| `time.js`、`ui.js`、`validate.js`、`amap.js`、`export.js`、`lead-builder.js` | `js` → `utils` 文件夹 |
| `amap-key.js` | `config` 文件夹 |
| `base.css`、`layout.css`、`pages.css` | `css` 文件夹 |
| `README.md`、`docs/` 里的 .md 文档 | `docs` 文件夹 / 根目录 |

> ⚠️ 血泪教训：如果把 `input.js` 传到根目录、而不是 `js/pages` 里，应用**完全不会读它**，你改了半天线上还是老样子。**这是最常见的「改了没生效」原因。**

---

## 一、基础操作：怎么进入文件夹上传文件

GitHub 网页上传文件的三种姿势，任选其一：

### 方式 A：逐级点进文件夹上传（最稳，推荐）

1. 浏览器打开你的仓库：`https://github.com/你的用户名/-APP`
2. 点文件名旁的**蓝色文件夹图标**进入子文件夹（比如 `js`）
3. 进去后再点 `pages`（或 `utils`）
4. 点文件夹右上角 **「Add file」→「Upload files」**
5. 把本地文件**拖进**灰色虚线区域（可一次拖多个）
6. 滚动到底部，点绿色按钮 **「Commit changes」**（提交提示文字不用改）

### 方式 B：从根目录一路点到目标文件夹

- 仓库首页 → 点 `js` → 进到目标子文件夹（如 `js/pages`）→ 右上角 Add file → Upload files → 拖文件 → Commit

### 方式 C：直接在 GitHub 在线编辑（改小文件最快）

- 进到目标文件夹 → 点你要改的文件 → 点右上角**小铅笔图标（✏️）** → 在线改内容 → 点绿色 **Commit changes**

## 二、更新某个功能的完整流程（以后都这么做）

假设你改了一个文件（比如 `input.js`），要让它生效：

1. **找对位置**：`input.js` 属于 `js/pages/` → 进 `js` → `pages`
2. **上传**：Add file → Upload files → 拖入 `input.js` → Commit
3. **等生效**：GitHub Pages 大约 1~3 分钟自动发布
4. **强制刷新**：电脑浏览器按 `Ctrl + F5`（或 Ctrl+Shift+R）强刷；手机浏览器关掉重开
   - 若之前**安装过 PWA（添加到主屏幕）**，需要：卸载应用 → 重新用浏览器打开 → 再「添加到主屏幕」（只做一次，以后小更新不用）
5. **验证**：打开应用页面，看你要的功能是不是生效了

### 如果我一次改了多个文件？

每个文件按上表放到各自的文件夹，**可以分几次上传**，最后统一等 3 分钟再刷新测试。

---

## 三、只改了传错位置的文件，怎么清理（可选但建议）

如果根目录里躺着不该有的文件（比如之前误传的 `input.js`、`store.js`、`export.js` 等），建议删掉避免混淆：

1. 仓库首页 → 点开根目录里那个多余文件（如 `input.js`）
2. 点右上角**垃圾桶图标**（Delete file）
3. 滑到底点绿色 **Commit changes**
4. 重复清理其它散落文件

> 清理只删错误位置的副本，**不影响 `js/pages/input.js` 里的正确文件**，放心删。

---

## 四、怎么确认我传对位置了？（验证方法）

拿 `input.js` 举例：

1. 仓库首页 → 点 `js` 文件夹 → 点 `pages` 文件夹 → 点 `input.js`
2. 看页面里的**文件内容**，搜索关键字（比如新版有 `remark`，旧版有 `feeLevel`）：
   - 在文件内容页按 `Ctrl + F` 输入 `remark` → 能找到 = 传的是新版 ✅
   - 或者看内容里有没有 `资费水平` → 有 = 还是旧版 ❌
3. 同时**看一眼地址栏 URL**：如果开头是 `github.com/你的用户名/-APP/blob/main/js/pages/input.js` 就是对的位置。

---

## 五、以后更新最快路径（记住 3 句）

1. **先想**：这个文件对应哪个文件夹？（看上表）
2. **再传**：点进那个文件夹 → Upload files → 拖文件 → Commit
3. **后刷**：等 1~3 分钟 → 强刷 / 重开页面

## 附：常见问题

| 问题 | 原因 | 解决 |
|---|---|---|
| 改了没反应，还是旧样子 | ① 文件传错目录（最常见） | 检查文件是否在正确文件夹（见第四节） |
| | ② 浏览器缓存了旧页面 | 按 Ctrl+F5 强刷，或关掉页面重开 |
| | ③ 还没到生效时间 | 等 1~3 分钟再看 |
| 装过 PWA 后一直旧版 | SW 缓存锁死旧 JS | 卸载 PWA 重装一次（以后不会再有） |
| 根目录好多重复文件 | 之前误传 | 按第三节清理 |
| 不清楚文件在不在线上 | — | 在 GitHub 仓库里按第四节逐级查看、搜内容 |
